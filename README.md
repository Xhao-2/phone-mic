# PhoneMic

**把手机当成电脑的麦克风。** 手机负责采集，电脑负责降噪后播放到一个虚拟音频设备，于是微信、QQ、Zoom、Discord、OBS、游戏语音里都能把手机当作麦克风使用。

- 电脑端：`PhoneMicServer.exe`（Windows 10/11，带图形界面的单文件程序，无需安装 .NET）
- 手机端：`PhoneMic.apk`（Android 7.0 及以上）

两者都在 [Releases](../../releases) 里，由 GitHub Actions 自动构建。

**当前版本：v1.1**

## 它是怎么工作的

```
 手机麦克风 ──► AudioRecord 48kHz 单声道 PCM16
                        │
                        │  UDP，每 10 ms 一个包
                        ▼
             PhoneMicServer.exe
                        │  抖动缓冲 + 重排序
                        │  降噪：80 Hz 高通 → 自适应噪声门
                        ▼
              VB-Audio "CABLE Input"
                        │
                        ▼
        CABLE Output ＝ 系统里的一个麦克风
                        │
                        ▼
         微信 / QQ / Zoom / Discord / OBS
```

### 为什么必须装 VB-Audio Virtual Cable

Windows 不允许普通程序凭空创建一个音频输入设备，那需要经过签名的内核驱动。所以「虚拟麦克风」这件事本身一定有驱动参与，所有同类工具（WO Mic、DroidCam 的麦克风模式）都是这么做的。

本项目的做法是不重复造驱动，而是复用免费成熟的 **VB-Audio Virtual Cable**：程序把声音播放进 `CABLE Input`，系统和其它软件就把 `CABLE Output` 当成一个麦克风。少了这一步，`PhoneMicServer.exe` 只会把手机的声音从音箱放出来，不会出现在任何软件的麦克风列表里。

## 快速开始

### 1. 电脑端

1. 安装 [VB-Audio Virtual Cable](https://vb-audio.com/Cable/)，装完重启一次。
2. 从 [Releases](../../releases) 下载 `PhoneMicServer.exe`，双击运行。
3. 窗口会自动选中 `CABLE Input`，面板上也会显示本机 IP。
4. 点「开始」，然后保持窗口开着。

### 2. 手机端

1. 安装 `PhoneMic.apk`（第一次安装需要在系统里允许「安装未知来源应用」）。
2. 手机和电脑连同一个局域网（有线网 + Wi-Fi 也算，只要在同一个路由器下）。
3. 打开 PhoneMic，填入电脑上显示的 IP 和端口 `8765`，点「开始」。
4. 允许麦克风权限和通知权限。

### 3. 在其它软件里选用

打开微信 / QQ / Zoom / Discord / OBS，把**麦克风**选成：

```
CABLE Output (VB-Audio Virtual Cable)
```

**不要**选 `CABLE Input`，那是我们播放端写入的方向。

## 电脑端界面说明

| 区域 | 作用 |
|---|---|
| 输出设备 | 列出所有播放设备，自动选中名字含 `CABLE Input` 的那个。装了第二条虚拟线（CABLE-B）可以点「刷新」后手动选 |
| 网络 | 端口默认 8765；缓冲默认 60 ms，网络不稳可以调到 100–150；右侧显示本机所有 IPv4，手机要填的就是其中一个 |
| 降噪 | 「启用降噪」开关 + 强度 0–10 滑杆 |
| 开始 / 停止 | 启动或停止接收。停止后可以改设备、端口、降噪参数再重新开始 |
| 电平表 | 显示当前音量。对着手机说话应该明显跳动，不跳说明没有收到音频 |
| 状态 | 「等待手机连接…」→「已连接 192.168.1.23:52134」 |
| 统计 | 收包数、丢包数、当前缓冲毫秒数 |
| 日志 | 启动信息、设备选择结果、错误原因 |

## 降噪是怎么做的

风扇噪音有两类成分：低频的转动轰鸣，和宽带的「呼呼」气流声。v1.1 用两级处理：

1. **80 Hz 二阶高通滤波**。切掉低频轰鸣，人声的基频（男声约 85–180 Hz，女声约 165–255 Hz）基本不受影响。
2. **自适应噪声门（向下扩展器）**。程序持续跟踪最近的「最安静电平」作为噪声底，把门限设在底噪之上 4–14 dB（滑杆对应的就是这个余量）。低于门限时增益压到 −30 dB，高于门限时正常放行。增益是逐采样点平滑的（起音 4 ms、释放 140 ms），所以不会有「咔哒」声或明显的呼吸感。

**强度怎么调**：默认 5。风扇离得远、底噪小就调到 3–4，保留更多说话开头的气音；风扇就在旁边、底噪很大就调到 7–8。调到 10 会明显「削」掉说话的第一个字，一般不建议。

**它能做到什么、做不到什么**：

- 能做到：说话间歇完全安静、底噪大幅下降、录音听起来干净。
- 做不到：**说话的同时**把背景噪声从人声里彻底分离出来——那需要频谱减法或 AI 降噪，是另一个量级的工程。所以如果风扇噪音特别大，除了调高强度，更现实的办法是把手机放远一点，或者给风扇降速。

## 协议说明

每个 UDP 包 = 16 字节头 + 960 字节 PCM，正好 10 ms 音频。

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 4 | 魔数 `PMIC`（小端 `0x43494D50`） |
| 4 | 4 | 序号，uint32，递增 |
| 8 | 8 | 发送端单调时钟，毫秒 |
| 16 | 960 | PCM S16LE，48000 Hz，单声道，480 个采样点 |

选 UDP 而不是 TCP 的原因：TCP 的重传会造成队头阻塞，延迟会越积越大；语音要的是**稳定且可预测的延迟**，丢一两个包比整体卡顿好得多。

## 从源码构建

两种产物都由 `.github/workflows/build.yml` 在云端构建，推送 `main` 分支就会自动产出并发布。

本地构建：

```powershell
# 电脑端，需要 .NET 8 SDK
dotnet publish server/PhoneMicServer.csproj -c Release -o publish

# 手机端，需要 JDK 17 + Android SDK
cd android
gradle :app:assembleDebug
# 产物在 app/build/outputs/apk/debug/app-debug.apk
```

## 常见问题

**手机连不上电脑**

- 确认两台设备在同一个局域网。**电脑插网线、手机连这个路由器的 Wi-Fi，也是同一个局域网**，只要能互相 ping 通就行。
- Windows 防火墙第一次会弹窗询问，要允许**专用网络**。如果当时点了取消：控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 → 找到 PhoneMicServer.exe 勾上专用。
- 电脑上如果装了 VPN 或多张网卡，界面右侧会列出多个 IP，选和手机同一网段的那个。

**有声音但语音软件里没有麦克风**

- 没有装 VB-Audio Virtual Cable，或者装完没重启。
- 界面日志里如果写「没有找到 CABLE Input」，就是这个原因。

**延迟偏高 / 断断续续**

- 把「缓冲」调大，例如 100–150 ms，换取更稳的声音。
- 关掉手机上的省电模式，它可能限制后台网络。
- 尽量用 5 GHz Wi-Fi。

**手机锁屏后停止**

- 需要在系统设置里把 PhoneMic 的电池策略设为「不限制」或「允许后台活动」，各厂商的省电策略会杀掉前台服务。

**降噪后说话开头被吃掉**

- 把强度往低调，4 左右通常已经够用。

## 已知限制

- 只支持同一个局域网，没有做公网穿透。
- 降噪是滤波 + 噪声门，不是频谱降噪或 AI 降噪；说话的同时背景噪声仍在。
- APK 使用 debug 签名，因为把 release 签名密钥放进公开仓库并不安全。自己长期使用请用自己的密钥重新签名。
- 只传输麦克风，不传输系统声音（那是另一个方向，需要 WASAPI loopback）。
- 没有回声消除。如果同时用音箱外放，对方可能听到回声，建议戴耳机。
